### 设计推理里最值钱的一条：简单模型的可表示性边界

把 ideal-point 老师展开：`−w_f(o_f − μ_f(p))² = −w_f o_f² + 2w_f b_f o_f +
2w_f (Cp)_f o_f − const`。所以给简单模型加 `o²` 特征后，它**原则上能精确表示**：
未裁剪的 ideal-point 基础分、γ·fam 记忆项、ρ·rep satiation 项。它**表示不了**：
μ 的 [0,1] 裁剪、(Cp)² 人格二次项、N 温度（人格对全部打分项的乘性缩放 =
三阶交互，超出二阶双线性特征的表达力）。这三项就是 2A 里简单 vs 非线性
差距的预测来源——差距不再是笼统的"容量不足"，而是可以逐项归因的。
预注册假设（写在 pf §6b.1）：E1 诊断里简单模型跟不上 N 温度通道，
非线性模型（靠 e_p⊙e_o 乘性交互 + 多层非线性）跟得上。

### 审查抓到的三个问题（都已修复）

1. **输入校验不对称**（质量审查，Group A）。`case_inputs` 只拒绝"location 案例
   多带选中地点"，不拒绝"action 案例少带"。后者会静默填零向量——将来数据
   生成脚本若漏传地点，得到的是一批悄悄缺信息的脏数据而非报错。已补对称
   守卫 + 测试。教训：两个方向的约定要两个方向都校验。
2. **计划文本被后续修复搞过时**（实现者上报，Group C/D）。问题 1 的新守卫
   与施工计划里两段测试代码冲突（写计划时守卫还不存在）。实现者按规矩
   停下上报而未擅改，协调者修计划后继续。流程按设计运转的例子。
3. **一个"证明"其实什么都没证明**（整体终审，本轮最有价值的发现）。
   "简单模型精确拟合双线性老师"的测试通过是假象：
   - 40 个案例（约 140 个约束）对 228 个参数——欠定，任何老师都能被插值
     拟合。审查者实测：换上理论上不可表示的 ideal-point 老师，测试照样过。
   - 测试用的老师还开着 `lambda_N=1.5` 的 N 温度，而 N 温度恰在
     "不可表示"清单上——靶子本身就不在可表示范围内。
   - 修法：`lambda_N=0`（两层）+ 每类 200 案例（超定，插值混不过去）。
     修后 KL = 2.5e-9，才是真证明。
   - 为什么重要：2A 要把简单/非线性差距归因到 clip/(Cp)²/N 温度上，这个
     测试是那条论证链的实验地基；没修的话论文引用的是假证据。
   - 教训：**验证"可表示性"的测试必须同时满足（a）靶子确实在可表示类内、
     （b）约束数远大于参数数**，否则通过没有含义。这条对以后 2A 的
     泛化 split 设计同样适用——测试集必须真的在训练分布外，否则"泛化好"
     同样是假象。
